# 项目名称（建议）

**腾讯 EDR 终端遥测数据采集能力验证与测试基线构建**

---

# 一、项目背景

EDR（Endpoint Detection and Response，终端检测与响应）依赖终端遥测数据进行威胁检测、攻击溯源和安全分析。

不同 EDR 产品对于：

* 进程行为；
* 文件操作；
* 注册表修改；
* 网络通信；
* 系统配置变化；

等终端行为的采集范围和字段完整度存在差异。

本项目参考开源项目 **EDR-Telemetry** 中定义的终端遥测事件分类，对腾讯 EDR 产品的数据采集能力进行验证，建立一套可重复执行的测试样本和端到端测试 BASELINE，用于评估 EDR 的遥测覆盖能力。

---

# 二、项目目标

## 总目标

构建一套 **EDR 遥测采集能力自动化验证方案**：

> 通过主动触发 Windows 终端行为，验证腾讯 EDR 是否能够正确采集对应遥测事件，并评估事件字段完整性。

---

## 具体目标

### 1. 建立终端行为测试样本库

开发一系列无害测试程序/脚本，用于模拟：

* 进程行为；
* 文件行为；
* 注册表行为；
* 网络行为；
* 系统配置变化。

要求：

* 行为可重复；
* 行为可验证；
* 不依赖人工操作；
* 能够生成唯一测试标识。

---

### 2. 构建端到端测试 BASELINE

定义：

> 某个行为发生后，EDR 应该产生什么事件，以及事件应包含哪些字段。

例如：

测试：

```
创建文件
```

BASELINE：

```
预期事件：
File Create

关键字段：
√ 文件路径
√ 文件名
√ 操作进程
√ 用户
√ 时间
√ Hash（如果支持）
```

---

### 3. 验证腾讯 EDR 遥测能力

在带 EDR 环境运行：

```
测试样本
    ↓
Windows行为产生
    ↓
腾讯EDR Agent采集
    ↓
后台事件查询
    ↓
BASELINE比对
    ↓
生成测试结果
```

输出：

* 支持能力；
* 缺失能力；
* 字段完整性；
* 上报延迟；
* 异常问题。

# 四、测试能力范围（建议分阶段）

## 第一阶段：基础遥测能力

优先完成：

---

## 1. Process Activity（进程活动）

测试：

* 进程创建；
* 进程退出；
* 父子进程关系。

示例：

```
test.exe
    |
    └── notepad.exe
```

验证字段：

* Process Name
* PID
* Parent Process
* Command Line
* User
* Timestamp

---

## 2. File Activity（文件活动）

测试：

* 文件创建；
* 文件修改；
* 文件删除；
* 文件重命名。

验证：

* 文件路径；
* 文件名；
* 操作类型；
* 操作进程；
* 用户。

---

## 3. Registry Activity（注册表活动）

测试：

* Key 创建；
* Value 修改；
* Key 删除。

使用：

```
HKCU\Software\EDR-Test
```

避免影响系统。

验证：

* Registry Path；
* Value；
* 操作进程。

---

## 4. Network Activity（网络活动）

测试：

* DNS 查询；
* TCP连接；
* HTTP访问。

验证：

* 目标地址；
* 端口；
* 协议；
* 发起进程。

---

## 第二阶段：系统行为

扩展：

* Service 创建/删除；
* Scheduled Task；
* PowerShell Script Block；
* WMI；
* BITS；
* Named Pipe。

---

## 第三阶段：高级行为（可选）

包括：

* Process Injection；
* Driver Load；
* Credential Access。

难度较高，需要根据 EDR 支持情况决定。

# 六、模块设计

## 1. Test Sample Module（测试样本模块）

作用：

产生指定 Windows 行为。

目录：

```
samples/

process/
file/
registry/
network/
```

示例：

```
process_create.exe

file_create.py

registry_modify.py
```

---

## 2. Test Runner（执行调度模块）

负责：

* 选择测试项；
* 执行样本；
* 记录运行信息；
* 管理测试生命周期。

例如：

```
python runner.py --case file_create
```

输出：

```
Run ID:
20260804_001

Case:
file_create

Status:
SUCCESS
```

---

## 3. Baseline Module（测试基线模块）

保存：

测试定义：

```
case.yaml
```

例如：

```yaml
case:
  file_create

action:
  create test.txt

expected_event:
  FileCreate

required_fields:
  - path
  - process
  - user
```

---

## 4. Collector Module（数据采集模块）

作用：

获取 EDR 事件。

可能方式：

* EDR API；
* 控制台导出；
* 日志平台。

统一转换：

```json
{
 "event_type":"file_create",
 "process":"test.exe",
 "path":"xxx.txt"
}
```

---

## 5. Comparator Module（结果比对模块）

比较：

实际事件 VS BASELINE

输出：

```
PASS

PARTIAL

FAIL

NOT FOUND
```

---

## 6. Report Module（报告模块）

生成：

* JSON报告；
* HTML报告；
* 能力矩阵。

示例：

| 能力              | 结果 |
| --------------- | -- |
| Process Create  | ✅  |
| File Create     | ✅  |
| Registry Modify | ⚠️ |
